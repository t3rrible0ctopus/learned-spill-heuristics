PROJECT PITCH — LEARNED SPILL HEURISTICS

Hello, my project explores whether a machine-learning model can improve one decision made during register allocation in a compiler.

When a program needs more values at once than the processor has registers, some values must be spilled to memory. Choosing which values to spill affects the extra load and store operations added to the program. A conventional allocator uses a hand-designed heuristic for that choice. I built a comparison between that classical approach and a learned heuristic.

The system parses a small subset of three-address code, including arithmetic, branches, and loops. It performs liveness analysis, constructs an interference graph, and uses graph coloring to assign registers. For the learned approach, a random-forest regressor estimates the static load/store rewrite cost of spilling each value. Its training examples are generated by applying the spill-rewrite pass to training programs. The rewritten programs are also checked with an interpreter to confirm that their outputs match the originals.

I evaluated both approaches on three random seeds. Each seed uses 240 generated training programs and 60 separate held-out programs, tested with two, three, and four registers. Across the runs, the learned allocator slightly reduced average spills and added pseudo-instructions. For example, with four registers it averaged 0.62 added instructions per program, compared with 0.83 for the classical allocator. This is a modest improvement, not a dramatic one. The learned allocator also takes longer to make its decision: about 30 milliseconds in this experiment versus less than 0.1 milliseconds for the classical heuristic.

The main contribution is an end-to-end, reproducible experiment: the model predicts a measured spill-rewrite cost rather than copying a hand-written cost formula, and the evaluation checks both allocation validity and rewritten-program semantics. The current results are limited to generated programs and pseudo-TAC instruction counts. They do not demonstrate faster native code or production-compiler readiness. A useful next step would be testing on a broader set of real programs and measuring runtime or machine-level spill traffic.

In short, this project shows how a learned spill heuristic can be trained and compared fairly with a classical baseline, while also making the trade-off visible: small reductions in spill overhead come at a higher allocation-time cost.
